## Evidence and outstanding dependencies
- The supplied Ghost-VR-main.zip and AstroBotVR2-main (1).zip were inspected. Ghost VR contains PS5XR (native Vulkan runtime); its psvr2.c, vr_exports.h and xr_vulkan.c are the most relevant native reference. AstroBotVR2 is a PS4 compatibility agent, not a native app backend. The entire online project index is still not verified.
- Pulse https://github.com/shwan-ps5/pulse: platform/vr.h, platform/vr_ps5.cpp, platform/vr_eyes.cpp, AGENTS.md, docs/PS5-VR2-NOTES.md. Pulse uses OpenGL, 2048 square per eye, side-by-side triple-buffered tiled targets; native 60 Hz with 120 Hz reprojection on 13.60. Its firmware-specific export fallbacks cannot be used on 7.61. Its GPL code has not been copied into the MIT core. Preserve notices and satisfy combined-work obligations if integrating it later.
- CHEncore uses native Vulkan/RADV; toolkit dependencies and exact native application ABI must be validated before loading any VR libraries. No changes to PS5 or HMD firmware recommended.

## Implemented here (host-tested)
`ps5/vr/vr_core.hpp`: abstract runtime contract, aligned target checks, asymmetric Vulkan projection, pose/view and yaw-only recenter, time-interpolated drum hits and strums. Drum lanes use raw bit positions in the original engine (0 kick, 1–4 toms, 5–7 cymbals). The detector uses horizontal circular planes as an initial approximation; kick triggers, controller mapping, calibration and geometry remain to be wired. Keep measured input samples separate from predicted display poses. Tests are standalone, not added to the app CMake yet. The GhostRuntime adapter binds to the included psvr2 API; its tests mock hardware. vulkan_linear.hpp supplies the copy/barrier helper but has not been compiled here (Vulkan headers not installed). Identity script isolates game-data and song roots and blocks normal upstream update checks; all alternate QA and packaging/update routes require audit before hardware deployment. Existing test expectations and package metadata may need updating. No automatic push.

## Hardware-first integration milestones
1. **Vulkan target POC**: inspect GhostVR projects for native Vulkan/AGC memory interoperability, headset buffer registration, runtime lifecycle, tracking, synchronization, reprojection, audio/device enumeration and app metadata. Verify supported 7.61 symbols and structures; fail closed on unresolved exports. Use the GhostVR linear RGBA8 path instead of Pulse tiling: three coherent host-visible buffers, mapped pointer, side-by-side eyes, 256-byte alignment, explicit copy/barriers and fence. Verify GPU address ownership, exact color format, stride and visibility. Do not assume vkGetBufferDeviceAddress equals the address expected by the headset. Use GPU fences and compositor ownership before reusing a target. Render a single test pattern and cleanly stop before progressing.
2. **Cinema**: separate frame preparation from presentation in base/vulkanexamplebase.cpp (prepareFrame and submitFrame currently acquire/present the TV swapchain). Draw existing game into offscreen texture, then into a world-locked stereo quad; no TV present while compositor owns display. Original flat path is untouched. Verify menus, load, pause, exit, guitar/USB/MIDI, headset audio and calibration. On runtime failure cleanly return to TV only once ownership is released.
3. **Stereo**: split update/render in examples/cloneheronative/cloneheronative.cpp render() and buildCommandBuffer(); gameplay advances once per frame. Use independent per-eye matrices and uniform buffers, not currentBuffer alone. Rework updateGameplayProjection(), highway_view.hpp, viewport math, sprites and HUD for spatial positions and Vulkan clip conventions. Disable shake in VR; support distance, width, recenter, seated mode. Start with single player, then evaluate local multiplayer.
4. **Sense and haptics**: bind real measured poses and buttons to runtime contract, integrate menu events and pulse haptics with bounded duration; check device connection, pause on tracking loss, headset audio route. Preserve physical instrument paths. Test 60 Hz rendering with 120 Hz reprojection and input timestamps against audio-backed song clock; log missed deadlines.
5. **Instruments and stage**: transform tracked stick tips to centered stage coordinates; integrate DrumDetector events via DrumInput and audio clock (separate timestamped events, no duplicate hits), map kick to configurable trigger, handle velocity calibration and five-lane variants. GuitarDetector is an experimental strum gate, requires fret mapping and calibration. Add stage, lighting, audience using original or appropriately licensed assets, and adjust notes/HUD for comfort. Full features remain unimplemented until hardware integration and validation.
